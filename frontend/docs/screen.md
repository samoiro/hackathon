# 화면 구성

화면을 만들 때 따르는 뼈대, 너비, 여백, 글자 배치 기준입니다. 색과 글자 토큰 값은 `design.md`, 컴포넌트 규칙은 `components.md`를 봅니다.

- **API 전 상태 확인**: API를 연결하기 전에는 상태를 쿼리 문자열로 확인합니다(`?status=error`, `?state=empty`). 이런 임시 분기에는 `shortcut:` 주석을 답니다.

## 2. 모든 화면의 뼈대: `AppLayout`

```
┌ 본문 바로가기 링크 (포커스 때만 보임)
├ 헤더 AppHeader  · 높이 72 · surface 바탕 · 아래 divider 선
├ main#main       · 위 32 · 아래 64 · 좌우 80
└ 푸터            · surface 바탕 · 위 divider 선 · 두 줄
  배경: canvas + 화면 아래 두 겹 물결(body::before/after)
```

- **페이지 시작**: 모든 페이지는 `<AppLayout title="…">`로 시작합니다.
  - `title`은 `문서 제목 | 사모이로`가 됩니다.
  - 앱 안에서 이동하면 `main`으로 포커스가 옮겨갑니다.
- **너비**:

  | 사용                             | 헤더·푸터        | 본문                       |
  | -------------------------------- | ---------------- | -------------------------- |
  | 기본                             | `max-w-[1280px]` | 같음                       |
  | `wide` (대시보드)                | `max-w-[1440px]` | 같음 (좌우 80을 빼면 1280) |
  | `width="max-w-[720px]"` (브리핑) | 기본 그대로      | 본문만 좁게                |

- **헤더 (v3)**: `로고 | 상황 영역 | 글자·화면 설정` 세 칸입니다.
  - **로고**: 고정이고 `/dashboard`로 갑니다. 이름은 전기안전체 Bold `text-title`, 슬로건은 전기안전체 Regular `text-tag`입니다.
  - **상황 영역**: 화면마다 하나만 둡니다. 입력과 분석 화면은 `StepIndicator`, 대시보드는 가게 버튼(가게 이름과 업종, 누르면 수정)입니다. 안내 문구, STEP 배지, 상태 표시는 헤더에 넣지 않고 본문으로 보냅니다.
  - **설정 버튼**: '가 + 반쯤 찬 원' 아이콘 하나입니다. 지금 상태는 팝오버 안의 체크로만 보여줍니다. 첫 방문 때 한 번만 안내 말풍선을 띄웁니다(`showSettingsCoach`).
- **푸터 두 줄** (글자 `text-caption`, `muted`):
  - 첫 줄: 서비스 이름(왼쪽), "매일 오전 7시 갱신"(오른쪽)
  - 둘째 줄: 데이터 출처(왼쪽), 서체 출처(오른쪽). 전기안전체 출처 표시는 지우면 안 됩니다.

## 3. 그리드와 너비 (PC 1440)

| 화면           | 구성                                                           | 클래스                                                          |
| -------------- | -------------------------------------------------------------- | --------------------------------------------------------------- |
| 가게 정보 입력 | 왼쪽 입력 736 : 오른쪽 요약 360, 사이 24                       | `grid-cols-[minmax(0,736fr)_minmax(0,360fr)] gap-6`             |
| 분석 중·실패   | 가운데 카드 하나, 본문 너비 720                                | `AppLayout width="max-w-[720px]"`                               |
| 대시보드       | 맨 위 강조 블록(전체 너비) 아래 왼쪽 855 : 오른쪽 400, 사이 24 | `grid-cols-[minmax(0,855fr)_minmax(0,400fr)] items-start gap-6` |

- **열 너비**: 열은 `minmax(0, Nfr)`로 비율을 지정합니다. 그래야 긴 내용이 열을 밀어내지 않습니다.
- **열 정렬**: 높이가 다른 카드가 나란히 놓이면 `items-start`를 씁니다.
- **대시보드 순서**:
  - 왼쪽(주요 정보): 주변 예정 행사 → 관심 품목 가격 → 이 지역은 어떤가요
  - 오른쪽(할 일과 보조): 오늘 확인할 일 → 마감 임박 지원사업
  - 맨 아래 전체 너비: 어떤 근거를 확인했나요
- **탭 금지**: 내용을 바꾸지 않는 탭 모양을 쓰지 않습니다(리뷰 F-03). 섹션은 세로로 이어서 보여줍니다.

## 4. 여백 (4의 배수만)

| 값  | Tailwind | 쓰는 곳                                             |
| --- | -------- | --------------------------------------------------- |
| 4   | `1`      | 제목과 바로 아래 설명                               |
| 8   | `2`      | 한 묶음 안의 항목(칩, 목록, 버튼 묶음)              |
| 12  | `3`      | 안쪽 블록 안의 작은 그룹, 아이콘과 수치 사이        |
| 16  | `4`      | 카드 안 그룹 사이, 안쪽 블록 여백, 모바일 카드 사이 |
| 20  | `5`      | 모바일 카드 안쪽 여백                               |
| 24  | `6`      | PC 카드 안쪽 여백(antd Card 기본), PC 카드 사이     |
| 32  | `8`      | 화면 위 여백, 상단 강조 블록 안쪽 여백              |
| 64  | `16`     | 화면 아래 여백                                      |
| 80  | `20`     | PC 좌우 여백 (모바일 16)                            |

- **임의 값 금지**: `p-[10px]` 같은 임의 값은 쓰지 않습니다. 배지 여백도 `4px 12px`입니다(리뷰 F-09).

## 5. 카드 안 구성

```
카드(antd Card, 모서리 16, 안쪽 24)
└ section aria-labelledby="…-heading"
  ├ 머리줄: h2(text-card) · 개수 배지 · (오른쪽) 보조 정보나 동작
  ├ 설명: text-caption muted (제목 아래 4)
  ├ 내용 (위 16)
  └ 출처·기준 시각: text-caption 또는 text-tag muted (맨 아래)
```

- **제목**: 카드 제목은 `h2`이고, 카드 안 소제목은 `h3`(`text-body-strong`)입니다. 화면 제목 `h1`은 한 화면에 하나입니다.
- **안쪽 블록**: `rounded-xl bg-canvas p-4`입니다. 선택할 수 있는 타일은 `border border-line-strong`이고, 선택되면 `primary-700` 테두리, `primary-50` 배경, 체크 아이콘을 씁니다.
- **수치 줄**: 신호 카드의 수치는 `text-display`이고 `flex items-center gap-3`로 놓습니다. 보조 단위(이번 주, 약 2.9만 명)는 `text-body muted`입니다.
- **출처와 기준 시각**: 데이터를 보여주는 카드에는 반드시 출처와 기준 시각을 적습니다(브랜드 약속 '근거').

## 6. 대시보드 상단 강조 블록

- **바탕**: `bg-hero`(밝은 화면 `#241A0D`, 어두운 화면 `#3A3A3F`), 모서리 20, 안쪽 32입니다. 글자는 흰색입니다.
- **머리**: 전신 캐릭터 88×86, 그 옆에 기준 시각(`text-caption`, `primary-300`)과 `h1 text-display`를 놓습니다.
- **신호 카드 3장**: `grid-cols-3 gap-4`로 놓습니다. 각 카드는 섹션으로 가는 링크(`href="#events"` 등)입니다.
  - 카드 머리: 아이콘(지름 32의 `canvas` 원) + `text-item` 라벨 + 오른쪽 `›`
  - 수치: `text-display`, 설명: `text-body`

## 7. 상태 화면

| 상태         | 처리                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------- |
| 데이터 없음  | 섹션 자리에 `EmptyState`(무엇이 없는지 + 다음에 할 일 버튼)를 둡니다. 섹션을 통째로 숨기지 않습니다   |
| 실패         | 무엇이 안 됐는지, 입력은 유지된다는 안내, 주 버튼 '다시 시도', 보조 '입력 화면으로 돌아가기'를 둡니다 |
| 오프라인     | 화면 위에 `OfflineNotice`가 다시 연결될 때까지 남습니다                                               |
| 불러오는 중  | 단계 목록과 진행률을 보여주고, 바뀌는 글자는 `aria-live="polite"`로 알립니다                          |
| 서울 밖 주소 | 오류 `Alert`로 알리고 확인 버튼을 비활성화합니다                                                      |

## 8. 모든 화면에서 확인할 것

- **너비와 확대**: 320px 너비와 200% 확대에서 가로 스크롤과 잘림이 없어야 합니다. 글자 크기 '아주 크게'에서도 버텨야 합니다(리뷰 F-06).
- **키보드**: 키보드만으로 모든 흐름을 끝낼 수 있어야 합니다. 포커스 링은 2px `fg` 색이고 2px 띄웁니다(`index.css`에서 전역 처리).
- **어두운 화면**: 화면 설정에서 바꿔 확인합니다. 색은 토큰이 바꾸므로 화면 코드에 다크 전용 분기를 넣지 않습니다.
- **확인 방법**: `npm run typecheck && npm run lint`를 통과하고, 실제 브라우저(`npx vite --port 5199`)에서 봅니다.
